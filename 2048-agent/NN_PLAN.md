# 2048 专用神经网络：可行性评估与实施方案

> 2026-10-24 · 承接 `AGENT_PLAN.md`（LLM 逐步对局）与 `README.md`
> 目标：写一个"看当前盘面 → 想一步 → 给方向"的神经网络，循环玩完整局，并接入现有回放/报告体系。

## 0. 结论

**可行，而且成本不高；但"纯神经网络直接吐方向"不是最强路线。**

- 2048 的博弈结构是"确定性移动 + 随机落子"，最强的公开方案一直是 **expectimax 搜索 + 手工评估函数**，不是 DQN；
- 神经网络在这里最有效的用法是 **当评估函数**（给每个候选盘面打分）放进 1–2 层前瞻，或者 **蒸馏** 一个搜索老师；
- 从零跑 DQN/PPO 能学会，但公开复现的分数普遍低于一步贪心，训练还慢，不推荐作为主路线。

**推荐路线（性价比最高）**：小 CNN 价值网 + 1–2 层 expectimax；用 expectimax 老师做监督冷启动，再用 afterstate TD 自博弈微调。
预期：**纯网一步 3k–10k 分，网 + 1 层前瞻 10k–30k，网 + 2 层 20k–60k**（同 seed 对比：贪心 4362，本地 4B 780，beam 840，DeepSeek flash 980）。

## 1. 先看现成方案（复用优先）

| 方案 | 做法 | 水平 | 能不能直接复用 |
| --- | --- | --- | --- |
| [nneonneo/2048-ai](https://github.com/nneonneo/2048-ai) | C++ expectimax + 启发式（单调性/平滑/空格/最大块） | 稳定 2048，深度加大可到 16384+ | 搜索与启发式可整体借鉴，**不是学习**，可当老师 |
| [Szubert & Jaśkowski, CIG 2014](https://doi.org/10.1109/cig.2014.6932907) | n-tuple 网络 + afterstate TD 学习 | 训练后可稳定 2048；大网络更高 | 纯学习路线的经典基线，CPU 可训 |
| 各类 DQN/PPO 复现 | 原始像素/盘面 → Q 值 | 多数 1k–5k，难超贪心 | 不建议 |
| 2048 的 AlphaZero 变体 | MCTS + 价值网 | 有到 2048 的，但算力/调参成本高 | 有余力再说 |

> 复用判断：**搜索框架照抄 nneonneo 的思路，学习部分自己写**——现有 Python 实现要么太慢、要么绑死特定网络结构，直接改不如按本仓环境重写一个 300 行的小实现。

## 2. 路线对比

| 路线 | 每步计算 | 预期均分 | 训练成本 | 实现难度 | 是不是"神经网络" |
| --- | --- | ---: | --- | --- | --- |
| A. expectimax + 启发式（对照基线） | 1–5 ms | 20k–100k | 0 | 低 | 否 |
| B. n-tuple + TD（纯学习） | <1 ms | 5k–50k | CPU 数小时 | 中 | 是（查表网络） |
| C. CNN 价值网 + 1–2 层前瞻 | 1–3 ms | **10k–60k** | CPU 1–2 h | 中 | 是 |
| D. 策略网蒸馏 expectimax | <0.5 ms | 3k–10k | CPU <1 h | 低 | 是 |
| E. DQN/PPO 从零 | <0.5 ms | 1k–5k | GPU 数小时+ | 高 | 是 |

**结论：主菜选 C，D 作为"最快能跑起来"的第一步，B 作为可选对照。**

## 3. 推荐实施方案（两阶段）

### Phase 1 · 策略蒸馏（半天内出第一版）

1. 用 expectimax（深度 2–3，启发式评估）当老师，跑 5–10 万局，记录 `(盘面, 老师选择的方向)`；
2. 训练一个 4 分类 CNN/MLP（输入 4×4 的 log2 编码），交叉熵；
3. 推理：一次前向 → argmax 方向，<0.5 ms/步，整局秒级跑完；
4. 产出：`--policy net` 可玩、可回放、可报告。

这一步的价值：**先把"神经网络真的在玩"的闭环打通**，分数预计 3k–10k（超过 4B/beam/DeepSeek，接近贪心）。

### Phase 2 · 价值网 + 前瞻（主结果）

1. 价值网 `V(afterstate)`：输入移动后、未生成新块的盘面（消除随机性），输出期望最终得分（对数尺度）；
2. 训练信号（两条都用）：
   - **蒸馏**：expectimax 的根节点值当标签（回归）；
   - **TD**：自博弈 `V(s_t) ← r + V(s_{t+1})`，afterstate 形式，n-step；
3. 决策：对 4 个合法方向各算 afterstate → `V` → 取最大；平局用启发式打破；
4. 升级：剩余空格少时切 2 层 expectimax（对随机落子做期望），分数再上一档；
5. 预期 10k–60k。

### Phase 3（可选）· 搜索内评估

把 `V` 塞进完整 expectimax（深度 3–4，随机落子按 0.9/0.1 加权），对比"纯启发式评估"和"网评估"，验证网是否真的学到了超越手工特征的东西。

## 4. 关键设计

- **状态表示**：4×4 指数（0..15）。CNN 用 16 通道 one-hot（每格一个 16 维向量）或 1 通道 log2/15；小网 3–5 层、<200k 参数即可。
- **afterstate**：只评估"移动后、未落新块"的盘面。这是 2048 的标准技巧：把随机性从评估里摘出去，样本效率高一个量级。
- **动作选择**：`argmax_d V(afterstate(s, d))`；非法方向直接排除；4 个值都极低时优先保空格。
- **搜索**：expectimax，spawn 只在空格均匀分布、2/4 按 0.9/0.1；深度 2 就够用，深度 3 在残局更强。
- **训练数据**：老师局 + 自博弈局混合；按分数分层采样（残局样本更值钱）。
- **评估协议**：固定 100 个 seed（与现有 `?seed=` 同一套），报告均值/中位数/最大块分布/2048 达成率；与 random、greedy、4B、beam、DeepSeek 同表对比。
- **可解释性**：每步把 4 个方向的预测值写进 `run.jsonl`，viewer/demo 的"决策"页签直接展示——这就是这个网络的"思考过程"。

## 5. 本机实测（可行性数据）

`nn2048/bench_env.py`（位棋盘：16 个 nibble 塞进一个 int，行移动查 65536 项表）：

| 指标 | 实测 |
| --- | --- |
| 单盘面移动吞吐 | **≈39 万 moves/s** |
| 随机策略整局吞吐 | **≈420 局/s**（200 局 0.48 s） |
| 随机策略均分 | **1148**（与既有 harness 基线 1149 一致，模拟器可信） |

推论：10M 步经验 ≈ 30–60 s 生成；小 CNN 在 CPU 上训练是分钟级，**不缺数据、不缺算力**。
（本机 torch 目前是 2.12.0+cpu；要 GPU 得另装 cu 版约 2.5 GB，但这个规模 CPU 足够，先不折腾。）

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 价值网精度不如手工启发式 | 先用"网 + 搜索"兜底；网只负责排序，不负责绝对分 |
| 蒸馏上限 = 老师 | 老师用深度 3；再用 TD 自博弈突破老师 |
| 评估方差大（随机落子） | 100 seed + 中位数/分位数，不只报均值 |
| 过拟合老师局面分布 | 自博弈数据混入，按空格数分层 |
| 训练/推理环境不一致 | 训练和 play.py 共用同一份 `env.py` 与编码函数 |

## 8. 验收标准

1. 固定 20 seed：**均值 > 一步贪心 4362**，最大块 ≥256 的比例 > 50%；
2. `--policy net` 能完整跑完一局，`run.jsonl` 里有每步 4 方向价值；
3. demo 回放能显示"网络给四个方向打的分"，报告里有与 LLM 各局的同表对比；
4. 推理 <5 ms/步（整局 <2 s），不依赖 GPU。

## 9. 与现有体系的集成点

- `play.py` 增加 `--policy net --net-model path.pt`：与 `greedy/random/llm` 同一套记录、回放、报告；
- `viewer.html` / `build_demo.py`：决策页签已有"四方向候选对比"，把 `gain/empties` 换成/并列 `V(d)` 即可；
- `README.md` 结果表加一行"NN（价值网 + 1 层前瞻）"，与 4B/beam/DeepSeek 同 seed 对比。
