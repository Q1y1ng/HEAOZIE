## 0. 结论摘要

| 指标 | 旧引擎（数组 + 手工特征） | 新引擎（bitboard + 概率截断） |
| --- | --- | --- |
| 搜索速度 | 约 0.4 M 节点/s | **15–18 M 节点/s** |
| 100 ms/步 的实际深度 | 4.2–4.6 | **5.8–6.2** |
| 8 局均分 | 37.6k | **238.7k** |
| 8 局最高 | 60.8k（4096） | **387.4k（16384）** |
| 最大块分布 | 4096 ×3 / 2048 ×4 / 1024 ×1 | **16384 ×4 / 8192 ×3 / 4096 ×1** |

一句话：**换棋盘表示 + 换评估口径，把同样的 100 ms/步 从"偶尔 4096"变成"一半局上 16384"。**

## 1. 引擎做了什么

1. **棋盘 = 一个 `uint64_t`**：16 个 4 bit 格（0 空、1=2、2=4、…），一格里存的是 log2。
   整块棋盘只占一个寄存器，移动/比较/TT 键都是原生 64 位操作。
2. **行查表移动**：65536 项的 `move_left[行] / move_right[行]`（含得分）。一次移动 = 4 次查表；
   上/下 = 转置后走左/右再转置回来。一次"四方向决策"只需 **3 次转置**（共享一次棋盘转置）。
3. **行查表评估**：与 nneonneo/2048-ai 同口径的逐行特征——行内 `sum^3.5`、单调性 `^4`、
   合并段数、空格数，权重 270/47/11/700。棋盘分 = 4 行 + 转置后 4 列，共 8 次查表，
   不再有 `pow`/`min` 在热路径里。
4. **置换表**：`key = 整个棋盘`、直映射 2^22 槽 × 16 B，带 `depth`；只有"干净值"（子树里
   没有发生概率截断的）才写回，避免把截断出来的近似值当精确值复用。
5. **概率截断**：期望节点按 spawn 概率往下传，累计概率 < `--prob-cut`（默认 1e-4）的分支
   不再展开、直接静态评估。效果是**自适应深度**：开局空格多（每层 ×14）3 层就截断，
   残局空格少（每层 ×4）能搜到 8–10 层。
6. **迭代加深 + 时间预算**：根节点从深度 1 逐层加深，用上一层的结果排序着法；
   超时的那一层整层丢弃，只用**完整搜完**的最后一层。
7. **自检**：`--selftest` 用独立实现（逐格数组 + 慢速特征循环）对拍转置、四方向移动、
   得分、评估值，20 万随机局面全部一致；否则不参与测速。

- 均分 **238,692**、中位数 232,746、最低 80,076、最高 **387,408**；
- 到块率：**16384 → 4/8（50%）**、8192 → 7/8、4096 → 8/8；
- 每步实际耗时 100.0–100.1 ms（`slow` = 0，即没有一步超出预算 2.5 倍）；
- 一局 4096 约 6 分钟、8192 约 12 分钟、16384 约 20 分钟（100 ms/步，8 局并行）。

**对照公开实现**（nneonneo/2048-ai，深度 8、约 1 s/步）：2048 100%、4096 97%、8192 76%、16384 13%。
本引擎在**只有其 1/10 时间预算**的情况下已经拿到 8192 7/8、16384 4/8，说明：
① 这套行查表评估的判别力很强；② 继续加预算/加种子还有上升空间（见 §4）。

## 3. 为什么这次能上台阶（与附录 A 的对照）

1. **评估口径换了**：旧引擎用"空格 + 单调 + 合并"的线性加权（权重是百分比级手工调的），
   新引擎用 nneonneo 的**幂律口径**（`sum^3.5`、`mono^4` 再乘 11/47/700/270）。
   旧的线性口径下 `wPower` 只能表达"格子等级之和"，幂律口径下"大块的价值"是指数级放大的——
   这正是 4096→8192→16384 需要的激励（一块 16384 的 `^3.5` 是 2048 的 200 倍）。
2. **速度换深度**：同预算下深度从 4.5 → 6.0，多出来的一层半正好覆盖"两步后才暴露的死形"。
   旧引擎加深反而变差（见附录 A 的 seed 4），是因为评估函数本身选不出更好的形；
   评估对了，加深才开始赚。
3. **概率截断替代了均匀采样**：旧的 `chanceCap` 是对空格**均匀抽样**（有偏），
   新的做法是**全展开 + 按概率剪枝**（无偏，且把算力集中在"会发生"的分支上）。

## 5. 复现方式

```powershell
cd 2048-agent\nn2048
# 单局（可 --save 出逐步 JSON）
.\engine_bb.exe --games 1 --budget 100 --seed 1 --save bb_seed1.json
# 8 局并行统计
py -3 bench.py --exe engine_bb.exe --seeds 8 --budget 100 --parallel 8 --start-seed 1
# 自检（表/转置/移动/评估对拍）
.\engine_bb.exe --selftest
# 只测速度与深度，不跑完整局
.\engine_bb.exe --bench-moves 200 --budget 100
```

编译（clang 16，不需要 MSVC）：

```powershell
clang++ -O3 -std=c++17 -D_CRT_SECURE_NO_WARNINGS -o engine_bb.exe engine_bb.cpp
```

## 附录 C. 学习型评估（NN_PLAN.md 路线）还需不需要？

- 现在的 238k 均分已经**大幅超过**"手工特征只能到 60k"的旧判断，那条结论作废：
  它是在**错误的口径**下得出的。
- n-tuple TD 的公开水平是均分 ~600k、32768 到 70%。要在本机复制，成本是几小时训练 + 损失函数调参；
  而**继续加搜索预算**几乎确定还能拿到 32768（nneonneo 深度 8 就有 16384 13%，我们的深度 6 已经 16384 50%，
  说明单位算力的收益还没榨干）。
- 结论：**先把搜索侧榨干**（预算/权重/端局），学习型评估留作下一阶段。
